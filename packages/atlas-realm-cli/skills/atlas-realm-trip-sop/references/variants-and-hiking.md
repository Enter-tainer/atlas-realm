# 备用 / 徒步 / 可选 / 切换 的写法

核心原则：**主备状态不占用颜色通道**。颜色只表达「时段/单元」，主备靠线型 + 透明度 + label 后缀表达；否则一旦有备选路线，色带就被污染。

## 1. 备用行程（Plan B / 绕行 / 替代路线）

| 通道   | 取值                                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------------------- |
| 颜色   | **与主线同色**（同一单元）                                                                                 |
| 线型   | `dashed`（或 `dotted`）                                                                                    |
| 透明度 | `0.45–0.55`                                                                                                |
| 线宽   | `3.5`（比主线细）                                                                                          |
| label  | 后缀 `(备选)`                                                                                              |
| note   | **第一行就是触发条件**                                                                                     |
| 排序   | 放在**同层末尾**：`annotations reorder` 时把主线 id 排在备选之前（`sortKey` 由服务端维护，不接受手工指定） |

```bash
atlas-realm ... annotations add route --layer-id <当天图层-uuid> \
  --waypoints "142.26834,44.72394;142.4,44.5;142.17,44.31" \
  --geometry "<OSRM 备选路线点串>" \
  --profile driving --label "🚗 音威子府→朱鞠内湖 (备选)" \
  --color "#7c3aed" --width 3.5 --opacity 0.5 --line-style dashed \
  --distance-text "62km" --duration-text "1h5m" --directed true --json
```

note 模板：

```
🚗 8/9 **备选路线 Plan B**
⚠️ 触发: 国道275号 大雨/落石 通行止
📏 62km | ⏱ 1h5m
→ 音威子府 分岔 | → 名寄 接回主线
[道路情报](https://...)
```

规则：

- **起讫点必须与主线的分岔点 / 汇合点重合**，切图时才能看出怎么切回来。
- 备选线也要真实 `geometry`（OSRM），不能手绘直线。
- 不要另开「备选」层——否则每次对比都要开关图层。
- 整段替换的多日方案（如“全改去道东”）才单独成层：`🔁 备选 · 道东方案`，并设 `visible=false`。

## 2. 徒步 / 非机动车行程

- **独立成层**：一个徒步日 = 一层，层名 `🥾 Day 4 8/8 礼文 桃岩コース`。
- **样式**：`--profile walking --line-style dotted --width 4 --opacity 0.85 --directed true`，颜色继承当天单元色。
- **徒步与接驳分开画**：巴士/船 = `dashed` + `driving` profile，徒步 = `dotted` + `walking` profile；**不要连成一条线**（否则看不出哪段要坐车）。
- 每个节点（登山口 / 展望台 / 终点）一个 point，label 带累计里程与耗时：`🥾 桃岩展望台 1.0km 30分`。

note 模板（徒步版必须含海拔 / 爬升 / 难度 / 接驳 / 风险）：

```
🥾 **桃岩展望台** — 最高点
📍 海拔 225m | 利尻富士展望
📏 登山口→展望台 1.0km | ⏱ 30分 (预计 09:18 到达)
📈 累计爬升 110m | 难度 ★
🚌 接驳: 香深港 08:40 → 桃岩登山口 08:48 (宗谷バス)
⚠️ 展望台~元地灯台 丘陵尾根·强风注意
```

徒步段 route 的 note 也同理：

```
🥾 桃岩登山口→展望台
📏 1.0km | ⏱ 30分(官方剖面图)
铺装步道·难度★
08:48 到登山口, 展望台约 09:18
```

难度用 `★`～`★★★★★`；风险用 `⚠️`；爬升用 `📈`。

## 3. 可选加点（optional stop）

- 仍用 point，label 后缀 `(可选)`，颜色继承当天单元色。
- note 写清条件：`若时间够 / 若天气好 / 若还有精力`。
- **不要为可选点单独画 route**（会污染线网）；必须画就用 `dotted` + `opacity 0.45`。
- 例：`🛏️ 幾春別炭鉱(可选)` + note `8/10 optional，若 16:00 前到夕张则顺路`。

## 4. 切换逻辑（两套计划二选一）

把切换条件写在**决策点**那条 note 里，两个方向都画出来，一主一备：

```
🏝️ **利尻岛 / 礼文岛 二选一** — 8/7-8
⛴️ 稚内港出发，两个岛天气差异大
※ 天气最好的那天去礼文岛(提前取消另一岛的观光巴士预约)
→ 利尻: 观光A(09:05-12:15) | 礼文: 桃岩徒步 + 观光B(14:15-16:40)
```

- 主方案：`solid` + `opacity 0.9`，无后缀；备方案：`dashed` + `opacity 0.5` + `(备选)`。
- 两个方向的**接驳时刻都写全**，并在决策点 note 里给出判断依据（天气/体力/封路）。
- 只影响单日的互换 → 都放同一层；整段多日替换 → `🔁` 单独成层 + `visible=false`。

## 5. 已取消 / 已完成

- **不删除**：`layers hide <id>` 或 `annotations update <id> --patch-file` 把 visible 置 false，保留可追溯。
- 已完成的行程建议保留原样，在 note 顶部加 `✅ 已完成 8/3`（不另起颜色）。

## 6. 检查清单

- [ ] 备选线的颜色与主线**完全一致**（不另起色相）
- [ ] 备选线 `dashed` + `opacity ≤ 0.55` + label 后缀 `(备选)`
- [ ] 备选线 note 第一行是**触发条件**，且起讫点与主线分岔/汇合点重合
- [ ] 徒步线 `dotted` + `walking` profile，且与接驳线（`dashed` + `driving`）分开
- [ ] 徒步点 note 含海拔 / 累计爬升 / 难度★ / 接驳时刻 / 风险
- [ ] 可选点有 `(可选)` 后缀与触发条件
- [ ] 备选线放在同层末尾；整段 Plan B 单独成层且 `visible=false`
